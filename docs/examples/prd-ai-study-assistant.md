# 示例：大学生 AI 学习助手 PRD

## 使用场景

- 文档类型：PRD
- 使用 Skill：系统默认 PRD Skill
- 输出格式：结构化 PRD
- 产品阶段：想法验证

## 输入信息

```text
我想做一个面向大学生的 AI 学习助手。

用户在复习时经常发现自己没有真正理解某些知识点，只是看过笔记或刷过题。
产品希望通过追问、错题复盘和知识点卡片帮助他们发现薄弱点，并进行巩固。

第一版不要做完整课程平台，也不要做社交功能。
希望能在 2-3 周内做出 MVP，用来验证学生是否愿意持续使用。
```

## 参数配置

```text
行业 / 领域：教育
目标用户：大学生
产品阶段：想法验证
关注重点：用户场景、痛点、MVP、风险
输出详细度：标准
```

## 输出节选

```markdown
# PRD：大学生 AI 学习助手 MVP

## 1. 背景与问题

大学生在复习中常见的问题不是“没有资料”，而是难以判断自己是否真正理解知识点。
很多学生会反复阅读笔记、刷题或看视频，但缺少能持续追问和复盘的工具。

## 2. 目标用户

| 用户类型 | 典型场景 | 核心痛点 |
|---|---|---|
| 考前复习学生 | 期末前集中复习 | 不知道哪些知识点没掌握 |
| 自学课程学生 | 看网课或教材后复盘 | 缺少即时追问和反馈 |
| 刷题学生 | 做错题后整理 | 只记答案，不理解原因 |

## 3. MVP 范围

### 3.1 本版包含

- 知识点输入：用户输入课程、章节或知识点。
- AI 追问：系统基于知识点连续提出理解检查问题。
- 薄弱点识别：根据用户回答标记可能不理解的概念。
- 错题复盘：用户粘贴错题或描述错误原因，系统生成复盘卡片。
- 复习卡片：将薄弱点整理为可再次练习的小卡片。

### 3.2 本版不包含

- 完整课程内容库
- 社交学习小组
- 直播课或教师端
- 复杂积分体系

## 4. 验收标准

- 用户可以输入一个知识点并完成不少于 3 轮追问。
- 系统能基于回答指出至少 1 个薄弱点。
- 用户可以保存一张复习卡片。
- 当用户回答信息不足时，系统需要继续追问，而不是直接给结论。

## 5. 风险与待验证

- 学生是否愿意用对话方式复习，而不是直接看答案。
- AI 追问是否会显得机械或过难。
- 复习卡片是否能带来持续使用。
```

## 为什么这个示例有价值

这个示例展示了 ProductGPT 适合把早期想法转成可交付 PRD，并明确 MVP 范围、验收标准和待验证风险。
